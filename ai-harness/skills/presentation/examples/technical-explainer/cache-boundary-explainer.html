architecture

The cache boundary belongs above generation, not inside it.

request assembly
stable prefix boundary
planner and tool policy
token generation
post-processing
# the boundary is computed before generation
prefix = assemble(system, tools, history)
key = fingerprint(prefix)

cached = lookup(key)
output = generate(cached, live_turn)
Cache Boundary Explainer3 / 7
sequence

The important step is the lookup before the new tokens begin.

01Assemble prefix.Stable instructions, tools, and durable context.
02Fingerprint boundary.The cache key is born here.
03Reuse prior state.Only valid work comes forward.
04Generate live turn.New tokens start after the boundary.

Cache Boundary Explainer5 / 7
failure modes

Most bugs come from caching material that was not actually stable.

!Hidden live state in the prefix.The cache reuses a previous assumption that should have been recomputed.
!Tool policy outside the key.Allowed behavior changes, but the cache still trusts old work.
!Unclear invalidation owner.Everyone can add context, but nobody owns when reuse stops.
Cache Boundary Explainer6 / 7
close

Cache the promise, not the accident.

Make the boundary explicit, keep live context after it, and include every behavior-changing policy in the key.
