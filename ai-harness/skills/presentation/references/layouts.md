# Layout primitives

A catalog of the layout primitives baked into `templates/theme.css`. Pick from these when laying out a slide; don't invent new ones unless the user's content genuinely demands it.

Each slide follows the three-row chrome:

```html
<section>
  <header class="slide-head">
    <span class="kicker">Section label</span>
    <h2>Slide title</h2>
  </header>
  <div class="slide-body">
    <!-- pick a primitive from below -->
  </div>
  <footer class="slide-foot">
    <span>Deck title <span class="dot"></span> Stable footer label</span>
    <span>N / Total</span>
  </footer>
</section>
```

The footer label is deck-wide metadata and should remain stable across sections. Use the kicker, divider title, or slide body to mark chapters such as `Appendix`.

The body grid has `align-content: center` by default — content clusters vertically center inside the body row. Use `.slide-body.top` to anchor to top instead, or `.slide-body.fill` to stretch (good for chart-only slides).

## Cards

The fundamental unit. A card is a bordered surface with a small uppercase kicker, an h4 title, and one or more paragraphs.

```html
<div class="card">
  <span class="card-kicker">Label</span>
  <h4>Headline.</h4>
  <p>Supporting text.</p>
</div>
```

**Variants:** `.card.accent` (yellow border + glow, "you are here"), `.card.positive` / `.card.negative` / `.card.info` (semantic soft backgrounds with deep text), `.card.flush` (no shadow — for cards inside another container).

## Grid layouts

For laying out 2–4 cards in a row.

| Class | Shape | Use when |
| --- | --- | --- |
| `.grid-2` | 2 equal columns | Before/after, two-card comparison, two questions |
| `.grid-3` | 3 equal columns | Three properties, three causes, three takeaways |
| `.grid-4` | 4 equal columns | Four-part framework |
| `.grid-2x2` | 2×2 matrix | Four metadata cards, four-quadrant model |
| `.split-l` | 2 columns 1:1 with stretched alignment | Hero metric + supporting cards |
| `.split-l-2` | 2:1 columns | Chart left, supporting cards right |
| `.split-r-2` | 1:2 columns | Single card left, content right |

## Before / after comparison

For showing a recommended shift, operating change, product transition, or old/new workflow.

Use a clear left-to-right structure:

- left panel: current state
- center: arrow or transition marker
- right panel: recommended/future state
- accent only the destination or key change

Keep each panel to 2-4 short items. If either side needs paragraphs, split the idea across slides.

Use `.compare`, `.compare-panel`, and `.compare-arrow`.

## Hero metric

For "the one number that matters" slides.

```html
<div class="hero-metric">
  <div class="display">6<span class="unit">hrs / wk</span></div>
  <p class="caption">What this number means.</p>
</div>
```

Pair with `.split-l` and a `.grid-2x2` of supporting context cards on the right.

## Numbered steps

For phased plans or ordered lists where order matters.

```html
<ol class="steps">
  <li><h4>Phase 1 — Seed</h4><p>What happens.</p></li>
  <li><h4>Phase 2 — Adopt</h4><p>What happens.</p></li>
</ol>
```

The numbering is auto-generated by CSS counter; don't write the numbers manually.

## Flow diagram

For three-step linear processes.

```html
<div class="flow">
  <div class="node"><strong>Hash</strong><span>tokens up to breakpoint</span></div>
  <div class="arrow">→</div>
  <div class="node accent"><strong>Lookup</strong><span>5-min TTL</span></div>
  <div class="arrow">→</div>
  <div class="node"><strong>Generate</strong><span>only new tokens</span></div>
</div>
```

`.node.accent` highlights the "active" or pivot step. Pair below with a `.grid-2` of detail cards.

## Relationship / tension diagram

For showing a person, team, system, or decision caught between two forces.

Use when the important point is not a process, but a structural tension: split accountability, competing priorities, duplicated ownership, or a mismatch between systems. Put the object under tension in the center, put the forces on the sides, and attach the consequences near the center.

Do not make this an org chart unless the org chart itself is the point.

Use `.relationship`, `.relationship-side`, `.relationship-center`, `.relationship-node`, and `.relationship-tags`.

## Movement / pipeline flow

For showing movement through a development path, operating loop, lifecycle, or talent/product funnel.

Use 3-5 stages with arrows. The middle stage can be accent-highlighted when it is the intervention or bottleneck. Each stage should have a short title and a few labels; avoid turning stages into paragraph cards.

Use `.pipeline`, `.pipeline-stage`, `.pipeline-arrow`, `.pipeline-grid`, and `.pipeline-note`.

## Summary / recommendation slide

For the final main-story landing point.

Use one dominant sentence plus 2-4 supporting items. The sentence should be plain and memorable; the support items should map back to the deck's core argument. Avoid vague titles like "Discussion" or "Next steps" unless they name the actual action.

## Section divider

For a transition into appendix, backup, or a new chapter.

Keep it sparse: big section name, one optional topic line, and minimal decoration. A divider should not introduce new evidence or ask the audience to process a full content slide.

When the divider introduces an appendix, use `Appendix` in the divider content or kicker, not in the shared footer label.

Use `<section class="section-divider">` with `.divider-rule` and `.divider-topic`.

## Prompt diagram

For annotating a piece of structured text with labeled lines.

```html
<div class="prompt-diagram">
  <div class="prompt-line muted"><span class="prompt-label">SYSTEM</span><span>50,000 tokens — instructions</span></div>
  <div class="prompt-line breakpoint"><span class="prompt-label accent-label">↳ breakpoint</span><span>cache key fingerprinted</span></div>
  <div class="prompt-line live"><span class="prompt-label">USER</span><span>200 tokens</span></div>
</div>
```

Variants: `.muted` (gray), `.live` (blue, "active"), `.breakpoint` (yellow accent fill, "the key thing").

## Pull-quote moment

For rhetorical beats between content slides. Use sparingly and only when the user wants a memorable spoken moment. Wrap the whole thing in `<section class="title-slide">`.

```html
<section class="title-slide">
  <header class="slide-head"><span class="kicker">moment</span></header>
  <div class="slide-body">
    <span class="kicker-cover">The thesis</span>
    <p class="pull-quote big">Big rhetorical line.<br>Second line.</p>
    <span class="pull-quote-cite">— attribution or context</span>
  </div>
  <footer class="slide-foot">…</footer>
</section>
```

Use sparingly: 1–2 per deck max, or it stops being a moment.

## Callouts

For emphasis under content. Goes at the bottom of a `.slide-body` after the main grid.

```html
<div class="callout">A line that summarizes.</div>
<div class="callout accent">When the point is the punchline.</div>
<div class="callout positive">For "good news" emphasis.</div>
<div class="callout negative">For "bad news" emphasis.</div>
```

## Check / cross lists

For "good fit / poor fit" comparisons inside `.card.positive` / `.card.negative`.

```html
<div class="card positive">
  <span class="card-kicker">Good fit</span>
  <h4>Use it when…</h4>
  <ul class="check">
    <li>Long stable prefixes</li>
    <li>Steady traffic</li>
  </ul>
</div>
```

## Chart wrapper

For Chart.js canvases. The wrapper provides the bordered surface; the host fills it.

```html
<div class="chart-wrap">
  <div class="chart-host"><canvas id="myChart"></canvas></div>
</div>
```

Pair with `.split-l-2` and supporting cards on the right.

## Code blocks

Standard `<pre><code class="language-...">` highlighted by highlight.js. Theme.css already styles the surrounding surface; the atom-one-light CDN handles tokens.

```html
<pre><code class="language-python">def hello():
    print("hello")
</code></pre>
```

## What's NOT here

Anything you'd find in a generic web design library — modals, accordions, tooltips, navigation menus. Slides don't need them.

If a slide's content doesn't fit any primitive above, the answer is usually "split it into two slides" before "invent a new primitive."
